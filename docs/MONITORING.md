# Мониторинг объявлений

Универсальный поиск с пятью критериями: город, состояние (`any/new/used`),
тип продавца (`any/private/shop`), минимальный рейтинг (0–5), максимальный возраст
объявления в минутах (1–1440). Для любого параметра можно оставить «Любое».
Поисковый запрос обязателен. Цена, память и другие товарные фильтры в мониторинг
пока не включены. Фиксированный интервал — 5 минут между завершёнными проверками.

## Панель

Вызовите MCP-инструмент `avito_monitor_panel` и откройте возвращённый локальный URL
в браузере клиента. В панели можно создавать поиски, приостанавливать и
возобновлять их, смотреть найденные объявления. Панель обновляет результат
каждые 5 секунд, а Avito запрашивается по пятиминутному расписанию.

Отдельный запуск, сохраняющий stdio-соединение живым:

```powershell
avito-ai monitor-panel
```

Оставляйте этот процесс и Chrome с локальным CDP запущенными. В постоянном
MCP-подключении клиент поддерживает серверный процесс сам. После закрытия
сервера мониторинг останавливается; сохранённые настройки и найденные события
восстанавливаются при следующем запуске. Мониторинг использует собственную
вкладку, закрывая только её. Существующие вкладки и переписки не читаются.

## Новые события

Первый успешный проход запоминает текущие ID без уведомлений. Далее
показываются впервые обнаруженные объявления, прошедшие все выбранные фильтры.
Один ID выдаётся один раз для каждого поиска, в том числе после перезапуска.
Изменение цены не создаёт новое событие. Изменение критериев сбрасывает базовую
выдачу и удаляет прежние события этого поиска. Пауза сохраняет историю ID.

`avito_monitor_save` создаёт поиск или изменяет его по `watch_id`.
`avito_monitor_list` возвращает настройки и состояние проверок.
`avito_monitor_enable` приостанавливает/возобновляет поиск.
`avito_monitor_events(after_id=0, watch_id=None, limit=100)` возвращает события
по возрастанию ID и `next_cursor`; пустой ответ сохраняет предыдущий курсор.
Бот в будущем сможет читать эту ленту, хранить последний доставленный ID и
избегать повторной отправки. Сейчас нет Telegram-токенов, webhook и отправки
сообщений куда-либо.

## Ограничения и точность

- Поиск сортируется через наблюдённый пункт «По дате», проверяются первые
  50 карточек. При высокой активности, продвижении и пропусках между проверками
  полнота не гарантируется; достижение лимита отмечается в панели.
- «Впервые найдено» и время публикации различаются. По времени используется
  дата публикации/обновления, которую показывает Avito; поднятие старого
  объявления может менять её. Неизвестное время не заменяется временем сбора.
- Город проверяется по местоположению карточки или её URL относительно
  наблюдённого, проверенного адреса городского поиска. Неизвестный город
  исключается при включённом городском фильтре.
- Тип продавца — вывод из описания с основаниями и уровнем уверенности,
  а не подтверждённый Avito статус аккаунта. Профили продавцов не открываются.
- Неизвестные состояние, рейтинг, тип или точное время исключаются, если
  соответствующий фильтр выбран. Это может исключать подходящие объявления.
- Описания новых кандидатов читаются только когда это нужно для фильтра.
  Максимум 10 страниц за проход, с паузами; остальные кандидаты сохраняются
  для следующих проходов. После HTTP 429 все поиски ждут 30 минут.

Настройки, ID и события хранятся локально в
`~/.avito-personal-mcp/monitor.sqlite3`, вне каталога исходного кода.
Опциональный `AVITO_MCP_MONITOR_DB` меняет путь. При ручном переносе базы в
репозиторий её надо исключить из публикации: она содержит пользовательские
поисковые критерии и результаты. Панель слушает только `127.0.0.1`, защищает
изменения от запросов с чужих сайтов и не содержит переписок, cookies и ключей.
